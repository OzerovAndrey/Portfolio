## 1. Мета

Зараз сайт — лендинг на один екран: hero → демо → три абзаци → CTA. Він обіцяє, але не показує глибини.
Мета v2 — показати **всю виконану роботу як доказ**: архітектуру токенів, пайплайн, автоперевірки, AI-ready скіл, компоненти, Figma-сторону й людину за цим.

Покупець дочитує до кінця, якщо на кожному скролі бачить **річ, яку можна перевірити** (цифру, код, діаграму, живе демо), а не слоган.

## 2. Аудиторія

## 3. Правила копі й цифр

1. **Цифри тільки з реєстру нижче.** Нова цифра → спершу рядок у реєстрі з джерелом. Оцінка без виміру → плашка `metric.typical`.
2. **Не обіцяти від імені Андрія** термінів, результатів і цін, яких він не підтвердив.
3. **Конкретика замість слоганів.** «Новий бренд — файл на 55 значень» краще, ніж «масштабується без зусиль».
4. **EN основна, UK повна.** Не дослівний переклад, а природна українська того ж обсягу. Ключі однакові.
5. **Без канцеляриту й води.** Одна думка на речення. Звертання: EN — «you», UK — «ви».
6. **H1 не довше ~26 символів і без дуже довгих слів** на мобільних (тимчасово, поки немає адаптивної типографіки — demo-03 п.4).

Навігація: Work (кейси) · Approach · Services · About · Contact. Демо лишається головним блоком Home.

### Home — порядок секцій

1. **Hero** — конкретне твердження + 2 CTA.
2. **Метрики** — 4–5 чисел з реєстру (компонент `metric` уже є в `components.json`).
3. **Живе демо** — перемикач бренду на сторінці (postMessage), diff-панель «що змінилось», мобільний постер замість iframe.
4. **Архітектура шарів** — інтерактивна діаграма + ланцюжок резолву одного токена в 4 брендах. **Генерується з `tokens/` під час білду**, не пишеться руками.
5. **Пайплайн** — Figma / Token Studio → Git → build → CSS → deploy, коротке відео.
6. **Якість** — автоперевірки + історія AA-знахідки з реальними цифрами.
7. **AI-ready** — скіл для Claude з токенів: агенти будують UI в межах системи.
8. **Компоненти** — Button, Input, Chip, картки лобі у 4 брендах поруч.
9. **Кейси** — картки → `/cases/*`.
10. **Для кого** — три ніші.
11. **Про мене** — коротко → `/about`.
12. **CTA** — форма / cal.com.

### `/approach`
Чому шари · бренд = дані, не код · Token Studio setup (скріни) · пайплайн · правила, які перевіряє CI (дослівно з чекера) · світла/темна як окрема вісь · що система **не** вирішує (контент, ілюстрації, motion, юридичні вимоги ринків).

### `/cases/*` — формат
Контекст (1 абзац) · проблема (3 пункти) · рішення (схема) · результат (3 числа з реєстру) · що зробив би інакше (1 абзац).

### `/services`
| Пакет | Для кого | Результат |
|---|---|---|
| DS Audit | Система є, не масштабується | Звіт: де hardcode, скільки коштує новий бренд зараз, план міграції |
| Token Architecture | Є UI-kit, немає токенів | Шари в Token Studio + Figma Variables, документація, перевірки |

Процес: дзвінок → аудит → пропозиція → робота спринтами → передача. Ціни не публікуються. Терміни — тільки з плашкою `metric.typical`.
